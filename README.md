## ⚠️ 请先读这四点（作者郑重声明）

1. **本插件目的是优化提示词**，节省因为书写提示词而消耗的时间，并帮助用户更准确地传达意思；**本质上是让 AI 可以多一步自我规划、约束**。
2. 本插件在 **DeepSeek-V4.1-Flash** 这种**能力较强、但发挥受提示词影响严重**的大模型上有**明显作用**。
3. 本人**仅使用此插件测试过部分 OneShot 类型**的任务，并在这些任务上取得了**突破性效果**；因此**无法保证此插件在所有任务中都能起到巨大的正向作用**，**建议对此插件的实际作用持保守意见**。
4. 本插件**完全开源**，支持**任何人、任何形式**使用并修改此插件，也**欢迎提出建议，以及各种测试**。

## 它做什么

你在输入框按回车的那一刻，消息**不会**直接发出去 —— 先由**另一个 AI（传话者）**把它整理成一条**可以直接发给工作 AI 的命令**，你看到满意结果再决定发送。

- 角色是**传话**，不是陪聊：优化 AI 明确知道自己是"把用户的意思转达给工作 AI"，**不回答你、不替你干活、不向你提问**；产出是命令正文本身（没有「优化后的提示词 / 改动说明」这类元话语），可原样发给下游 AI。
- 优化用的模型、档位、权限都**与对话本身独立**，不会动你的对话模型。
- **档位与权限按会话独立**：在 A 会话调到「极端 + 自动」，B 会话不受影响。
- **拦截卡按会话隔离**：A 会话触发的卡，切到 B 不会冒出来；切回 A 若还挂着（等你决定）会原样回来。
- **可以带上上下文**（可选，默认关）：让它知道"你刚才在聊什么"。默认只优化你这一句；菜单里可选最近 1/2/3/5/10 回合，或「全文」（与工作 AI 看到的上下文一致）。**上下文只喂你的原话全文**，工作 AI 的回复内容不会进入上下文。

作者：**啃轮胎的西狐** · 版本 **0.1.1beta1** · 版本日期 **2026/09/11**（插件内「使用帮助」面板最底部也有同样署名）

## 一、安装

### 方式 A：像安装其它 DSH 插件一样（推荐）

两步：先把包装进 profile，再把包名登记为 bundle 层。

```bash
# 1) 装包（GitHub 仓库 / tarball / 本地目录都行）
dsh plugin --profile web add github:WestFox-AwA/dsh-prompt-optimizer#v0.1.1-beta.1
dsh plugin --profile web add ./dsh-external-dsh-prompt-optimizer-0.1.1-beta.1.tgz

# 2) 在 ~/.dsh/profiles/web/package.json 的 dsh.profile.bundles 里加一行：
#      "@dsh-external/dsh-prompt-optimizer"
```

重启 DSH 即生效。**为什么还要改 bundles**：`dsh plugin` 只是把参数转发给 pnpm（只负责安装），而"哪些包作为 bundle 层参与装配"由 profile 的 `dsh.profile.bundles` 决定。本插件自带 `cordis.patch.yml`，会在装配时把自己的 entry 插进根条目表 —— 与 `@dsh-external/dsh-super-injector`、`@dsh-external/dsh-graded-mode` **完全同一写法**。

### 方式 B：不动 bundles，用 profile patch 插入

不想改 `dsh.profile.bundles` 时，也可以直接在 profile 的补丁层插一条 entry：

```yaml
# ~/.dsh/profiles/web/cordis.patch.yml （顶层 YAML 数组）
- insert:
    - id: prompt-optimizer
      name: '@dsh-external/dsh-prompt-optimizer'
      config: {}
```

包本身仍需可解析（`dsh plugin add` 装好，或手工放好 `node_modules` 软链/junction）。

> ⚠️ **方式 A 与方式 B 只能选一种**：两种都做会让同一条 entry 插入两次，启动时报 `duplicate loader entry id`。

### 验证安装

```bash
dsh --dump-config --profile web | grep -A2 'id: prompt-optimizer'   # 装配树里有它，且只有一条
node -e "console.log(require.resolve('@dsh-external/dsh-prompt-optimizer',{paths:['<profile 目录>']}))"
```

### 运行要求

- **DSH Web**（`dsh web`；本插件只在 web 平台提供 UI）。
- 至少一条可用的 LLM 路由（优化默认跟随当前会话模型；也可在插件的模型胶囊里单独指定）。
- 插件本身**零运行时依赖、无需构建**（`lib/` 里就是可直接运行的 JavaScript）。

## 二、30 秒上手

1. 在输入框正常打字，按 **Enter**（或点发送）。
2. 消息被拦下，**输入框上方**弹出一张折叠卡，头部一行显示状态（`优化中…` / `待确认` / `失败`）。
3. 权限为 **需要审查** 时：卡片会自动展开，**产出**就是将要发出的那条命令，可以直接编辑 → 点 **确认提交** 发出；不满意就 **重新生成**（会让你先填一个方向）。
4. 权限为 **自动输出** 时：优化一完成就自动发出，无需操作。
5. 不想优化了：点 **‹ 回退**（停优化 + 收起卡片 + **不发消息** + 原文留在输入框），或点 **放行原文** 直接按原文发出。

> 所有入口合并成了输入框底部的一枚胶囊 **`✦ 优化 <当前档位> ˅`**（就在「工作区内修改」右边）。点开是一个纵行菜单：**档位 / 权限 / 模型 / 使用帮助**。会话里和「新对话」页都是同一处、行为一致。

---

## 三、那一枚胶囊里有什么

点开输入框底部那枚 `✦ 优化 …` 胶囊，从上到下一共四组：

| 组 | 取值 | 说明 |
|---|---|---|
| **档位** | 关闭 / 普通 / 高级 / 极端 | 关闭＝完全不拦截，恢复原生发送；普通＝只把话说清楚（约 3 秒）；高级＝补上"显然需要"的约束与验收标准（约 20 秒）；极端＝**读取项目真实结构**（只读，不写盘）后给出分阶段行动计划 + 验收标准 + 多情况预案（约 20 秒） |
| **权限** | 需要审查 / 自动输出 | 审查＝产出可编辑，点「确认提交」才发；自动＝优化完成即自动发出（**失败也会按原文发出**，绝不静默吞消息）。档位为「关闭」时这一组置灰 |
| **上下文** | 不读取 / 最近 1·2·3·5·10 回合 / 全文 | 让优化 AI 知道"你刚才在聊什么"。**只喂你的原话全文**（单条上限 4000 字），工作 AI 的回复刻意**只保留长度与工具调用次数** —— 只借"你想要什么"，绝不把它的方案 / 结论 / 术语 / 口吻当成你的意图。选**全文**则把工作 AI 当前看到的完整上下文交给优化模型（预算 6 万字，超限**按整回合丢弃最早的**，绝不截断单条约束）。默认**不读取**（＝改动前的行为） |
| **模型** | 任意 provider/模型 | 只影响优化，不动对话模型。**按 provider 折叠**：默认每家只占一行（`▸ DeepSeek · 4 个模型`），点一下才展开该家的模型；**当前选中模型所在的那一家会在打开菜单时自动展开**，其余保持折叠，所以装了四五家 provider 菜单也不会拉得很长。某家 provider 连不上会被标注「不可达」，不会拖慢整张列表 |
| **使用帮助** | — | 简明教程（怎么用 / 档位 / 权限 / 拦截卡按钮 + 推荐组合）；面板左上角有 **‹ 返回** 回到菜单 |

> **想要发挥插件所有能力且自动化，建议【极端】+【自动】。**
>
> 上下文选哪个？**平时用「最近 3 回合」**（省 token、够用）；**需要它理解"现在聊到哪了"时用「全文」**（对齐工作 AI 的上下文，代价是每次多花几万字符）。

## 四、拦截卡

消息被拦下时，出现在**输入框正上方**（和官方待办面板、队列面板同一个位置）。

- **位置固定、不浮动**：宽度与输入框对齐，是页面布局里正常的一块 —— 不需要拖动、不需要改尺寸，也不会盖住对话内容。
- **可折叠**：头部一行（状态点 + 标题 + 状态 + token）本身就是开关。运行中默认收起、几乎不占地方；**审查态自动展开**，让你先看清要发什么。
- **产出是主角**：可直接编辑，高度随内容自动增长（只有真的超长时才出现唯一一条滚动条）。
- **「思考」「已查证」默认折成一行**：点标题才展开。「思考」标题右侧显示本次思考 token（provider 不上报时显示 `— tok`）。
- **动作栏固定四个按钮**：`‹ 回退` / `放行原文` / `重新生成` / `确认提交` —— 位置和数量在**任何状态下都不变**（运行中只是把暂时不可用的置灰），不会出现"换一组按钮让你重新找"。
- **状态一眼可辨**：`优化中…` 是脉冲蓝点、`待确认` 是绿点、`失败` 是红点；头部右侧显示本次总用量（如 `Σ 1.1k tok`）。
- **上下文徽标**：本次真的读入了对话时，头部会显示 `上下文 3 回合 · 598 字`（只统计你的原话；没读到就不显示）。
- **按会话隔离**：卡片属于触发它的那个会话。

## 五、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 按回车没反应，消息也没发出去 | 说明已进入优化流程 —— 看**输入框上方那张卡**的进度；若卡片不在视野，切到该会话即会出现 |
| 优化很慢 | 高级/极端档需要 20 秒左右（极端档还会读项目结构）。想快就用**普通档** |
| 提示"优化模型不可用 → 已按原文发出" | 所选模型连不上（例如本机 `ollama` 未启动）。插件会**自动回退到会话默认模型**，下次用默认模型 |
| 想临时不用 | 点胶囊 → 档位 → 选「关闭」 |
| 菜单里某家模型标「不可达」 | 该 provider 当前不可用（未启动/无权限），不影响其它模型 |
| 界面能换英文吗 | **暂时不能**，当前 UI 有且只有中文 |
| 它老是让我先建 goal / 列 todo，太啰嗦 | 这是**按难度判定**的结果：只有多点改动或命中高危信号（不可逆、动数据 schema、密钥、发布上线、对外兼容…）才会要求建目标 / 分阶段；单点小改只给一句命令 + 一句完成标志 |
| 选了「最近 3 回合」但头部没显示上下文徽标 | 说明这个会话里还没有可读的**你的原话**（新会话第一句就是如此）。徽标只在真的读到内容时才出现 |

## 六、卸载

```bash
dsh plugin --profile web remove @dsh-external/dsh-prompt-optimizer
```

若用"方式 B"安装，请同时删除 `cordis.patch.yml` 里那条 `insert`。插件设置存在 `~/.dsh/prompt-optimizer.json`（档位 / 权限 / 模型 / 按会话设置），如需彻底清理可一并删除。

## 七、实现要点（给想改代码的人）

- **两个半边**：`lib/index.js`（宿主：三档系统提示与传话框架、只读工具循环、SSE 流式运行、模型目录、状态落盘、HTTP 路由）＋ `lib/client.js`（浏览器：入口胶囊、纵行菜单、帮助面板、输入框上方的拦截卡、捕获阶段拦截回车与发送按钮）。
- **UI 尽量复用官方基元**：胶囊与它弹出的菜单用的是 shell 提供的 `@deepseek-ai/dsh-client-ui-primitives`（`Menu`、`Icon*16`、`useAnchoredPosition` 等），菜单外壳、行高、选中 ✓、portal 定位、点击外部关闭、视口夹取全部是官方实现 —— 所以它和 DSH 自己的菜单同款，也会随主题改版一起走。
- **挂载点**：入口胶囊挂 `conversation.input.left`（会话里与新对话页都在，行为一致），拦截卡挂 `conversation.input.dock`（与官方待办面板、队列面板同槽，是布局流里的正常占位，不浮动、不遮挡）。
- **拦截是捕获阶段**在 `window` 上做的（早于 React 与编辑器自身处理）：`Shift+Enter` 换行、`/` 命令、空草稿、仅附件、输入卡片之外的回车一律放行。
- **不改动官方发送链路**：确认发送时用官方 `inputActions.setDraft()` + `submit()`，与手动发送完全同一条路；「放行原文」用的是拦截那一刻存下的完整原文。
- 产物是纯 JavaScript（无构建步骤）；`ACCEPTANCE.md` 是逐格验收清单，`evidence/` 是机器留痕（自检报告、遥测、对照数据）。

## 八、隐私与边界

- 优化请求只发送**你的输入文本**，以及（高级/极端档）**当前项目的目录树摘要与关键文件名**；极端档的只读查证限定在项目根目录内，不写盘、不执行命令。
- 拦截卡默认不发送任何消息：只有「确认提交」/「自动输出」/「放行原文」三条路径会把内容交回官方发送链路。
- 本插件为客户端 + 宿主本地插件，不引入任何第三方服务。
